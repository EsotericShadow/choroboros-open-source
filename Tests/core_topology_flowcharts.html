Deep DSP Quirks Audit — All Findings

🔴 CRITICAL Findings

C6-A: Float-to-int without NaN guard — Lagrange5th, Cubic, PhaseWarp, Orbit, Tape   ✅ FIXED

All manual circular buffer cores computed int i0 = static_cast<int>(readPos). If readPos becomes NaN, static_cast<int>(NaN) is undefined behavior per C++ standard.

Fix applied: NaN guard if (!(readPos >= 0.0f)) readPos = 0.0f; — uses the !(x >= 0) form that catches NaN even with -ffast-math (unlike std::isnan). Cubic cores now share the guard via InterpolationUtils.h::readCubicInterp(). Lagrange5th and Tape have inline guards.

C6-B: Thiran intDelay cast from smoothed float — Thiran

const int intDelay = static_cast<int>(std::floor(totalDelay)) at line 208 of ChorusCoreThiran.cpp. Same C6 pattern — if totalDelay is NaN, std::floor(NaN) returns NaN, and the cast is UB. The jlimit upstream (line 200) guards against out-of-range values but NOT against NaN, because jlimit uses < / > comparisons which are all false for NaN.

Fix: Same NaN sanitization before the cast.

C6-C: BBD clockPhase double-to-int cast — BBD

const int intBefore = static_cast<int>(phaseBeforeInc) and const int intAfter = static_cast<int>(chan.clockPhase) at lines 125-126 of ChorusCoreBBD.cpp. If clockFreq becomes extremely large (e.g., due to a near-zero delaySeconds), clockPhase can overflow int range. The upstream jlimit on delayMs prevents this in normal operation, but the delaySeconds computation float delaySeconds = delayMs * 0.001f at line 245 could theoretically reach a very small value if delayMinMs is misconfigured.

Severity: Low — multiple guards upstream. But technically unchecked.

🟡 DANGEROUS Findings

D1-A: Thiran coefficient recomputation per-sample — Thiran

computeCoefficients() is called on every sample (line 237 in the non-boundary branch). This function performs a double-precision nested loop: ORDER=5 → 30 multiply/divide operations per call. That's ~150 FLOPs per sample per channel. No allocation (it writes to a pre-allocated std::array), so it's RT-safe, but it's the single heaviest per-sample cost in the entire plugin.

Not a correctness bug. Performance concern only. Could be optimized by interpolating coefficients between block-start and block-end values.

D1-B: BBD filter redesign every 32 samples — BBD   ✅ VERIFIED SAFE

At line 264: choroboros::designBBD5thOrderButterworth(targetCutoff, fs) is called every 32 samples. Verified: BBD5thOrderButterworthCoeffs is a plain struct of 13 floats, returned by value on the stack. setCoeffs() is plain struct assignment. Zero heap allocation. RT-safe.

D1-C: Tape smoothedDepth shared across channels — Tape   ✅ FIXED

smoothedDepth was a single member variable shared across the L/R per-sample loop, causing channel 1 to see a pre-smoothed value from channel 0's pass. Same bug existed in LinearEnsemble's smoothedColour.

Fix applied: Both smoothedDepth (Tape) and smoothedColour + colourInitialized (LinearEnsemble) are now std::array<float, 2> indexed per-channel. Eliminates L/R smoothing crosstalk.

🔵 SUBTLE Findings

S2-A: Denormal risk in BBD stage chain — BBD

The 256–2048 element stages array decays toward silence during clock periods with no new input. Low-amplitude values can hit denormal range. ScopedNoDenormals in the outer ChorusDSP::process() sets FTZ/DAZ flags. Mitigated.

S2-B: Denormal risk in Thiran allpass state — Thiran

The 5-element state[] array in each allpass instance processes through feedback. During silence, these states decay toward denormal territory. ScopedNoDenormals covers this. Mitigated.

S2-C: Tape phase offset leaky integrator — Tape

phaseOffset *= tapePhaseDamping (0.99999) decays very slowly. After 100,000 samples of silence (~2.3 s at 44.1 kHz), the offset is still 37% of its peak. If the initial value was very small (1e-20), the decay passes through denormal range. ScopedNoDenormals handles this. Mitigated.

S6-A: Lagrange5th weight computation — floating-point precision — Lagrange5th

The Lagrange weight loop weight *= (u - xj) / (xi - xj) accumulates round-off across 6 multiplied terms. When u is close to an integer, some weights become very small. Interpolation overshoot of ~0.001 dB possible. Inaudible, acceptable.

S-NEW-A: Thiran coefficient stability at low fractional delay — Thiran

When fracDelay approaches 0, the Thiran D value approaches ORDER (5.0). The jlimit(ORDER+0.01, ORDER+0.99, D) clamp prevents the worst case, but near D=5.01, coefficient accuracy degrades. The crossfade strategy masks this. Acceptable.

S-NEW-B: Thiran allpass state reset on boundary crossing creates transient — Thiran   ✅ FIXED

Was: newActive.state.fill(0.0f) zeroed the allpass state on every integer-delay boundary crossing, creating repeated transients the 48-sample crossfade couldn't fully mask. Root cause of "ping-pong aliasing" on slow Thiran sweeps.

Fix applied: newActive.state = oldActive.state — copies the settled DFII-T state from the fading allpass, giving the new allpass a warm start that preserves continuity across the crossfade.

S-NEW-C: BBD clock frequency at extreme depth — BBD

At very short delays, clock frequency can approach Nyquist. The 5th-order Butterworth input filter attenuates this, but at extreme settings may not fully suppress clock feedthrough. Intentional — BBD circuits have this exact behavior (it's the "character").

S-NEW-D: PhaseWarp and Orbit duplicate readCubic implementations — PhaseWarp, Orbit   ✅ FIXED

Was: Three identical readCubic() implementations in Cubic, PhaseWarped, and Orbit .cpp files.

Fix applied: Shared readCubicInterp() in new Source/Cores/InterpolationUtils.h. All three cores now have thin inline readCubic() wrappers in their headers that delegate to the shared function. NaN guard lives in one place.

S-NEW-E: Tape write-after-read ordering — Tape

In Tape, the saturated input is written to the buffer AFTER the read (line 284, after the read at line 264). This means the current sample's write doesn't contaminate the current sample's read. The effective minimum delay is 1 sample (enforced by guardSamples). Correct and intentional.
